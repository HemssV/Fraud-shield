# Assumptions & Limitations

1. **Git commands unavailable**: The `git` executable is not available in the current PowerShell environment. I will perform all file modifications within the `ml/` directory, but I cannot execute the required `git checkout` or `git commit` commands natively during this session. The user must manually handle source control operations outside this environment.
2. **Node vs Django endpoints**: The FastAPI service will expose `POST /score` (designed primarily for the Node.js payload/response) and `POST /predict` (designed for Django). However, both endpoints can return a superset of the required fields to accommodate any upstream logic.
3. **Velocity in `feature_importances`**: `fraudModel.js` does not include `velocity` in its output keys for `feature_importances`. I will include it in the new engine's output since it is requested in the Phase 5 instructions and parsed implicitly by some UI components.
4. **Golden Features**: To ensure parity without executing Node.js from Python, I will write `ml/scripts/make_golden.js` to execute the Node feature generator. If `featureGenerator.js` cannot be run entirely standalone (due to DB dependencies), I will supply mock objects directly identical to those in `mockData.js`.
5. **Generative Models**: LightGBM and IsolationForest are chosen. Due to the complexity of embedding IsolationForest out-of-fold directly during LightGBM training within a simple `train.py` script, I will train them concurrently on the train set and average/combine their risk signals in the `engine.py` logic, unless the out-of-fold pipeline can be implemented cleanly.
6. **Data generation scaling**: Generating 2000 shippers for 180 days might take a few minutes. I will ensure the Python generator script performs efficiently by using vectorized operations where possible, or iterating quickly with basic object dictionaries.
